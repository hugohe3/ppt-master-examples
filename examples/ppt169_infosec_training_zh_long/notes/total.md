# 01_cover

# 03_ch1_cover

第一章，为什么是你。这一章不讲操作，只解决一个认知问题。很多人默认安全事故是黑客攻破了系统，所以是技术部门的事。我们接下来用四页说明：泄露的根因里近一半与人直接相关，攻击者进门最常用的两类方式有一类是社会工程学，公安部通报的真实案件里攻击者甚至是应聘进来的，而你在这套风险里同时扮演三个角色。

---

# 04_human_factor

先看根因。IBM《数据泄露成本报告》二〇二六版的统计，恶意或犯罪攻击占全部泄露根因的百分之五十五，较上一年上升近百分之八；人为失误占百分之二十三；纯粹的 IT 故障只占百分之二十二。也就是说，真正与技术故障有关的只有四分之一左右，其余四分之三都要经过某一个人的操作。右边这个数字来自 Verizon 二〇二六年数据泄露调查报告：所谓人为因素出现在百分之六十二的数据泄露中，上一版是百分之六十。两份独立报告、两套口径，指向同一个结论：把人当成入口，比把系统当成入口更接近事实。

# 05_entry_paths

再看攻击者具体从哪条路进来。同一份 DBIR 报告统计了确认泄露的初始入侵途径：漏洞利用百分之三十一，升到第一位；钓鱼百分之十六，与上一版持平；凭据滥用百分之十三，由上一版的第一位降到第三；托词欺骗百分之六。这里要提醒一句读法：不要因为漏洞利用排第一就松口气。钓鱼加凭据滥用合计百分之二十九，与漏洞利用几乎持平，而这两条路和漏洞利用有一个根本区别——漏洞由 IT 部门修补，钓鱼和凭据只能由你守。这份数据集覆盖二〇二四年十月到二〇二五年十一月，是当期的。

# 06_insider_cases

统计之后看具体案子。这四起都是公开通报的，可以核验。第一起是公安部二〇二五年三月公布的北京海淀案：犯罪团伙制作木马程序，组织人员入职目标教培机构，定向投放木马非法控制内部计算机，抓获犯罪嫌疑人八名。请注意这个手法——攻击者不是黑进来的，是应聘进来的。第二起甘肃张掖案，团伙勾结快递行业工作人员窃取订单个人信息出售，抓获十八人，涉案三百余万元。第三起四川凉山案，嫌疑人利用开发运维在线学习平台的工作便利非法获取并出售个人信息，全案抓获四十五人。第四起是某药房内鬼盗卖客户数据，根源在于企业没有严格限制和监控员工的数据访问权限。规模上，二〇二四年全国公安机关侦破侵犯公民个人信息相关案件七千余起，这不是孤例。

# 07_ch1_takeaway

第一章收在这里。你在这套风险里同时有三个身份。第一个是目标：你的账号和你手里的数据本身就是战利品。第二个是通道：攻击者真正要的往往不是你，而是穿过你去拿系统里更值钱的东西，海淀案就是这个结构。第三个是防线：能在第一时间发现并说出异常的，通常只有当事人，也就是你。这三个身份是我们依据前面的通报案例与统计所作的归纳，页面上标了整理二字，不是引自单一来源。接下来第二章，账号与密码。

# 09_password_rules

先看口令。这张表左边是很多人被教了十年的老规矩，右边是现行的权威要求，依据是 NIST SP 800-63B-4，二〇二五年七月发布的版本。长度上，旧口径是八位够用，现在要求作为单因素认证的口令最少十五个字符，只有当口令仅仅是多因素认证的一个组成部分时才可以短到八个字符。定期更换这一条被直接推翻了：标准明确规定不得要求用户定期更换口令，只有在有证据表明口令已经泄露时才强制更换。组合规则同样被推翻，不得强制要求大小写、数字、符号混合。取而代之的是两条新要求：建立或修改口令时必须与已泄露口令的黑名单做完整比对，命中即拒绝并告知原因；找回方式上不得使用你的第一只宠物叫什么这类知识型问答，也不得存储可被未认证者访问的口令提示。一句话记住：长度优先于复杂度，不复用、不被撞库命中，比定期更换更重要。

---

# 10_mfa

很多人以为开了短信验证码就安全了。看三种现实中的绕过手法。第一种是语音钓鱼，攻击者冒充 IT 服务台打来电话，引导你把验证码念出来。第二种是推送轰炸，连续发送认证推送，直到你为了清静按下同意。第三种是 SIM 卡交换，把你的号码转到攻击者的卡上，短信验证码直接送到对方手里。这不是假设。CISA 与 FBI 等七国机构联合发布的 Scattered Spider 预警，二〇二三年首发、二〇二五年修订，明确指出拉斯维加斯 MGM、凯撒等赌场被攻破，是因为攻击者说服了 IT 服务台人员重置密码和多因素认证令牌。同一份预警给出的对策是：使用抗钓鱼的多因素认证，也就是 FIDO 或 WebAuthn，或者基于 PKI 的 MFA，因为它们不受推送轰炸和 SIM 卡交换影响。落到个人只有一句：没有任何人有权在电话里让你念出验证码。

# 11_phish_email

这一页左边是我们自己画的邮件界面示意，不是真实邮件，也不是截图，界面里的文字只是教学示例。请按编号看六处破绽。第一处，显示名写的是 IT 服务台，但第二处的实际地址里把 service 拼成了 s-e-r-v-1-c-e，用数字一替换了字母 i——CNCERT 二〇二六年的提示里明确说，这批钓鱼域名大量使用字母重复、缺字、错拼的仿冒手法，常见关键词是 zh、cn、apps、web、office。第三处是主题，紧急加上二十四小时内未验证将停用账号，制造的是时限压力。第四处是链接，显示文字和实际指向不一致。第五处是附件，文件名是双扩展名，而且要求你先关掉安全提示再打开——正常的公司邮件不会这样要求。第六处是页脚，缺少任何可以核对的组织信息。这六处是我们依据 CNCERT 与 CISA 的公开提示归纳的，顺序不代表权重。判断标准是：单独一处不足以定案，两处同时出现就该停手。处置方式也很简单，看不准就不点，转给安全负责人比自己去验证要安全得多。

# 12_phish_channels

如果你把钓鱼等同于钓鱼邮件，就会漏掉三条路。第一条是语音和短信：DBIR 的钓鱼演练数据显示，这类以移动端为载体的渠道，成功点击率的中位数比电子邮件渠道高出百分之四十。第二条是搜索结果：CNCERT 二〇二六年五月的风险提示说，黑产通过 bing 搜索引擎优化投递高仿真钓鱼站点，并且检测 refer 头以规避分析，你直接输域名访问还会被跳转——也就是说，搜出来的下载站同样是入口。第三条是仿冒办公软件：在二〇二六年二月六日到五月四日注册的四百三十九个钓鱼域名里，仿冒 wps 和 chrome 的合计三百四十个，占百分之七十七点四。下面这张图是 IBM 二〇二六年报告按初始攻击途径统计的平均泄露成本，单位是万美元：语音与短信钓鱼五百二十九万，冒充服务台等社会工程学五百二十三万，有效账户滥用五百零七万。三条社工路径的平均成本几乎一样高，而钓鱼已经连续第四年是进入被泄露组织的头号初始攻击途径。

# 13_ch2_takeaway

第二章的三件事。今天就做的：把公司账号的口令换成十五个字符以上、而且没有在别处用过的一串。本周做的：在支持的系统上启用抗钓鱼的多因素认证，不要再只依赖短信验证码。长期保持的：任何催你立刻、马上、否则的消息，先停手再核实，电话、短信、搜索结果和邮件一视同仁。这三条是本章要点的归纳。下一章我们从账号转到你手上的数据和设备。

# 15_data_grades

先建立一把尺子。这四档从左到右敏感度和外发限制递增。公开类，已经对外发布过的，可以自由外发。内部类，仅限在职员工，外发需要业务负责人确认。敏感类，包括客户与员工的个人信息、合同与报价，外发需要安全与法务确认，并且要留痕。最高一档是重要数据，由主管部门目录认定，处理者必须定期开展风险评估并向主管部门报送报告。这套分级不是我们凭空造的，法定依据在下面：《网络安全法》第二十三条第四项要求采取数据分类、重要数据备份和加密等措施；《数据安全法》第三十条要求重要数据处理者定期开展风险评估并报送；《个人信息保护法》第五十一条要求对个人信息实行分类管理并采取加密、去标识化等技术措施。但四档的名称和具体外发口径是我们做的可执行归纳，页面上标了整理，不同企业的分级名称可能不同，请以本企业制度为准。分不清的时候，按敏感处理。

---

# 16_removable_media

这一页只讲一条路径：可移动介质。IBM 二〇二六年报告显示，接近百分之十的数据泄露中，攻击者是通过可移动介质非法复制数据的。真正的问题不是这个占比，而是右边这个数字：这一类泄露平均需要两百五十八天才被识别和遏制，与供应链入侵并列耗时最长。为什么最难被发现？不是因为它更严重，而是因为它离开了所有能被监测到的通道——数据一旦落到一块私人硬盘上，日志里就没有它了。所以这一条的要求是：不要用私人 U 盘和移动硬盘转运公司数据；确实必须使用时，走公司审批和加密介质。

---

# 17_remote_work

在家办公不是换个地方打开电脑，而是把办公室的边界搬到了你家，所以同一套标准要跟着走。设备上，公司数据只落在公司管控的终端上，个人电脑不做公司数据的落地存储。网络上，在公共 Wi-Fi 下要先连公司 VPN 再访问内部系统，不要为了网速快绕过管控通道。账号上，家人共用的电脑不保存公司账号口令，离开座位时锁屏。屏幕和音频上，视频会议共享屏幕之前先关掉无关窗口，客户信息不要出现在共享画面里。这四个场景是我们归纳的常见远程办公风险面。最后一句请记住：《网络安全法》第二十三条要求留存相关的网络日志不少于六个月，你在家的操作同样在日志里。

# 18_export_check

第三章收在四个问题上，它们是一条逐级过滤的序列。第一问，这是哪一档数据？分不清就按敏感处理。第二问，收件人有权知道吗？对外发送要有合同或授权依据。第三问，有没有更小的范围？能发摘要就不发全量，能去标识化就不发原始个人信息。第四问，留痕了吗？谁批的、什么时候发的、发了哪一版，要能查得到。这四问是我们依据《个人信息保护法》第五条到第七条的合法、正当、必要与影响最小原则做的操作化归纳。判断规则只有一条：任何一句答不上来，就不要发。下一章讲后果。

# 20_law_renumber

先说条号。《网络安全法》二〇二五年十月二十八日由十四届全国人大常委会第十八次会议作出修改决定，这是这部法律自二〇一六年制定以来的首次修改。修正后全文八十一条，比二〇一六年版净增两条，导致第十二条之后的条文序号整体后移。表里是十项对照：用户行为红线由第十二条变为第十三条；等级保护与日志留存六个月由第二十一条变为第二十三条；应急预案与事件报告由第二十五条变为第二十七条；禁止危害网络安全活动由第二十七条变为第二十九条；个人信息的三条由第四十一到四十三条变为第四十三到四十五条；等保义务罚则由第五十九条变为第六十一条；危害网络安全活动罚则由第六十三条变为第六十六条；侵害个人信息罚则由第六十四条变为第七十一条，而且改成了转致条款，实践中转引《个人信息保护法》。下面这段是最容易写错的地方，请特别注意：修正后第八十一条仍然写着本法自二〇一七年六月一日起施行，二〇二六年一月一日是修改决定的生效日，不是这部法律的施行日。正确的说法是：《网络安全法》二〇二五年修正，修正后的规定自二〇二六年一月一日起施行。

# 21_three_laws

三部法律，各管一段。《网络安全法》管的是你用网络做的每一件事：第十三条第二款规定任何个人和组织使用网络不得危害网络安全，不得利用网络从事危害国家安全、侵害他人名誉隐私知识产权等活动；第二十九条还有一条容易被忽略的——明知他人从事危害网络安全活动，仍然提供技术支持、广告推广、支付结算等帮助的，同样违法。换成人话就是：帮朋友跑个脚本，同样违法。《数据安全法》二〇二一年九月一日施行，第三十二条规定任何组织、个人收集数据应当采取合法、正当的方式，不得窃取或者以其他非法方式获取数据；第二十七条要求企业建立全流程数据安全管理制度并组织开展数据安全教育培训——这门课本身就是这一条的落实。《个人信息保护法》二〇二一年十一月一日施行，第十条规定任何组织、个人不得非法收集、使用、加工、传输他人个人信息，不得非法买卖、提供或者公开；第五十一条第四项要求个人信息处理者合理确定操作权限，并定期对从业人员进行安全教育和培训。所以，个人信息的每一次经手，都在这两条里。

# 22_penalty_ladder

现在看代价。这张表的关键不在单位那一列，而在直接责任人员那一列。《网络安全法》第六十一条：不履行第二十三条、第二十七条义务的，单位一万到五万元，拒不改正或者导致危害后果的五万到五十万元，对直接负责的主管人员和其他直接责任人员处一万到十万元；本次修正新增的第三款加重了这个尺度——造成大量数据泄露等严重后果的，单位五十万到二百万元，个人五万到二十万元；造成特别严重后果的，单位二百万到一千万元，个人二十万到一百万元。《数据安全法》第四十五条的结构相同，严重情形下单位五十万到二百万元，个人五万到二十万元，还可以责令停业整顿、吊销执照。《个人信息保护法》第六十六条更重：情节严重的可处五千万元以下或者上一年度营业额百分之五以下罚款，直接责任人员十万到一百万元，并且可以禁止其在一定期限内担任相关企业的董事、监事、高级管理人员和个人信息保护负责人。最后一列是钱之外的后果：《网络安全法》第六十六条第三款规定，因从事危害网络安全活动受到治安管理处罚的，五年内不得从事网络安全管理和网络运营关键岗位工作；受到刑事处罚的，终身不得从事。罚款有上限，任职资格没有。

# 23_criminal_threshold

再往上一层是刑事责任。《刑法》第二百五十三条之一规定了侵犯公民个人信息罪，法释〔2017〕10 号司法解释自二〇一七年六月一日起施行，给出了情节严重的数量门槛：行踪轨迹、通信内容、征信、财产信息五十条以上；住宿、通信记录、健康生理、交易等信息五百条以上；其他公民个人信息五千条以上；违法所得五千元以上。关键在下面这条规则——将在履行职责或者提供服务过程中获得的公民个人信息出售或者提供给他人的，数量或者数额达到上述标准一半以上即构成情节严重。按这个规则折算，对在职员工而言就是二十五条、二百五十条、二千五百条，违法所得二千五百元。同样一份名单，你因为是员工，入罪门槛只要一半。行政层面也不是纸面威慑：二〇二二年七月二十一日国家互联网信息办公室对滴滴全球股份有限公司处八十点二六亿元罚款，同时对董事长兼首席执行官程维、总裁柳青各处一百万元罚款；二〇二三年九月一日对知网责令停止违法处理个人信息并处五千万元罚款，其手机知网等十四款应用存在违反必要原则收集、未经同意收集、未提供账号注销功能等行为。罚企业和罚个人，是同时发生的。

# 25_first_four_hours

发现异常之后，顺序比速度更重要。第一个动作是停：停止正在进行的操作，不关机、不重装、不删除日志和邮件。《国家网络安全事件报告管理办法》第七条把现场保护情况列为必报内容，你把现场清理干净，等于把证据一起清掉了。第二个动作是报：立即通知本单位安全负责人，由单位按预案启动处置并向主管部门报告，这对应《网络安全法》第二十七条。第三个动作是记：记下发现的时间、现象和你做过的每一步操作，《个人信息保护法》第五十七条对通知内容有明确要求，这些信息是写通知的原材料。第四个动作是配合：配合调查与溯源，处置结束后单位要在三十日内形成事件处置总结报告，按原渠道上报。下面这条时限请记住：按《网络安全事件分级指南》研判属于较大以上网络安全事件的，一般网络运营者最迟四小时内向属地省级网信部门报告。这四个动作是我们依据上述法条与办法归纳的员工侧序列。

# 26_report_channels

报给谁，看你所在单位的类型。涉及关键信息基础设施的网络运营者，第一时间向保护工作部门和公安机关报告，最迟不超过一小时。中央和国家机关各部门及其直属单位，向本部门网信工作机构报告，最迟不超过两小时。绝大多数企业适用的是高亮这一行：其他网络运营者，向属地省级网信部门报告，最迟不超过四小时。适用前提是研判属于较大以上网络安全事件，不是所有异常都要上报。制度依据是《国家网络安全事件报告管理办法》，国家互联网信息办公室二〇二五年九月十五日发布，二〇二五年十一月一日起施行，共十四条，已经生效。渠道有六类：12387 热线电话、12387 网络安全事件报告平台网站、微信 12387 小程序、国家互联网应急中心 CNCERT 微信公众号、专用邮箱和传真。最后补一句：处置中如果发现涉嫌违法犯罪的线索，还应当按规定向公安机关、国家安全机关报案，这是《网络数据安全管理条例》第十一条的要求。

# 27_report_immunity

很多人不敢上报，是担心报上去先挨罚，于是选择自己消化。这一页就是回答这个顾虑的。《国家网络安全事件报告管理办法》第十一条原文写得很清楚：发生网络安全事件时，网络运营者已经采取合理必要的防护措施、按照应急预案进行处置并有效降低影响危害、并且按照本办法规定及时报告的，可以视情从轻或者不予追究相关单位和人员责任。三个条件要同时满足：已采取合理必要防护措施，按预案处置并有效降低危害，按规定及时报告。前两个条件通常由公司体系承担，第三个条件的触发点在你。所以结论是：你越早说，公司越有可能落到从轻或不予追究这一侧；隐瞒只会把时间线拖到无法补救。及时上报是免责条款，不是追责起点。

# 28_quiz

最后五道判断题，先各自判断，我再公布答案。全部五道的答案都是错。第一题错，因为 IBM 二〇二六年报告显示 IT 故障只占根因的百分之二十二，最高的是恶意或犯罪攻击百分之五十五。第二题错，NIST SP 800-63B-4 明确规定不得要求用户定期更换口令，只有在有证据表明口令已泄露时才强制更换。第三题错，IBM 报告显示接近百分之十的泄露通过可移动介质发生，而且这类泄露平均两百五十八天才被识别和遏制，恰恰是最难被发现的一条路径。第四题错，《网络安全法》第六十一条对直接负责的主管人员和其他直接责任人员规定了独立罚款，第六十六条第三款还规定了五年内乃至终身的禁业。第五题错，正确顺序是先保护现场、立即上报，研判属于较大以上事件的最迟四小时内报告；自己先查清楚会破坏现场，也会错过报告时限，反而失去从轻或不予追究的机会。这五道题是我们依据前面引用的法条与统计自行设计的，答案以页内引用的来源为准。今天的课到这里，谢谢各位。
